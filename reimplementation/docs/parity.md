# Component-editing subset

- EDIT-1 implemented: empty document and in-memory Input, Output, AND, OR and NOT descriptors, positions, labels, validated commands, snapshot undo/redo and dirty state. Headless engine tests exercise history, IDs, invalid commands and redo preservation.
- EDIT-2 implemented: palette, canvas grid, selection, movement, deletion, shortcuts and visible errors. Components are drawn from the original generated symbols (see Vector assets); labels are separate runtime text. Headless egui tests exercise placement, focus ownership, rendered errors, selection, drag cancellation, history and shortcuts; native interaction, all palette choices and light/dark appearance remain unverified.
- EDIT-3 implemented: explicit pin-to-pin wires (click or keyboard pin picking, deletion, undo). A wire joins the two named pins; geometry, crossings and coincident pins never connect anything. Same-direction wires are allowed while editing and judged when simulating.
- SIM-1 implemented (one-bit, acyclic): `src/simulation.rs` compiles pin nets (exactly one output driver per net, no floating receiving pins, no feedback, limits of 10,000 components, 30,000 wires and 80,000 work units); `src/runtime.rs` evaluates Input, Output, AND, OR and NOT with Digital's read-then-publish microstep; `src/engine.rs` owns the runtime outside the document and history, starts transactionally and rejects every edit, undo and redo while it runs; `src/ui.rs` provides Start/Stop/Step/Settle (buttons and F5, Shift+F5, F10, F6), idle/pending/settled/error status, input toggles (panel list, canvas click, Space), text value badges (`= 1`, `= 0`, `= ?`), an edit-lock explanation, cancellation of placement/wire/drag gestures on start, located compile errors in the visible error path and settle chunks of 2,048 work units per frame with a repaint requested while work remains, so Stop is handled between chunks. Headless tests cover the engine and the egui paths (start, toggle, step, settle, stop, edit and undo; invalid circuits; blocked pointer and keyboard edits; gesture cancellation; multi-frame settling with Stop). Digital references: `core/Model.java` (microsteps), `draw/model/NetList.java` (Digital also joins nets by geometry, which this editor deliberately does not), source revision d118dce079b6b8867024d40f9b14dfa667e52106.
- Simulation gaps: compilation and each settle chunk run on the UI thread within the documented limits (no worker, so no cancellation or stale-result handling was needed or built); a toggle is refused while work is pending; unconnected gate inputs are errors where Digital would let them float; no feedback or randomized startup, high-Z, contention, buses, clocks, sequential components, memory, hierarchy, measurement or tests; settle oscillation limits are not applicable because cycles are rejected. Passing these tests is not Digital parity.
- Persistence (partial, not M3 completion): `src/formats.rs` exposes `formats::parse_v2(bytes)`, `formats::serialize_v2(&DigV2)`, and a format-specific `DigV2` model. The subset is strict UTF-8 Digital `.dig` v2 XML with empty circuit attributes, ordered visual elements (`elementName`, empty or one `Label` string entry, integer `pos`), ordered wire endpoints, and absent/empty measurement ordering. Wire endpoint geometry is preserved as written (including diagonal, reversed and zero-length segments); element/wire order, arbitrary element names, signed i32 coordinates, and `None` versus `Some("")` labels round-trip semantically. The deterministic writer emits an XML 1.0 UTF-8 declaration, version 2, empty circuit attributes and the represented visual elements/wires; measurement ordering is omitted because this model cannot represent it. XML text escaping preserves Unicode, tab/LF and CR via numeric references, including CR-versus-LF semantics, and escapes ampersand, less-than and greater-than. Writer errors are typed and include element/field context. Both directions bound element/wire counts at 10,000/30,000 and decoded strings at 4 KiB; parser limits also include 4 MiB input, depth 32 and 64 attributes per XML element, and writer construction is capped incrementally at 4 MiB output. Coordinates are signed i32. The parser checks text outside the document element as literal XML whitespace before entity decoding; entities remain decoded inside fields. The parser rejects v0/v1/future versions and unsupported/extra fields, attributes, resources, rotation, metadata or measurement values rather than discarding data. At the Feature 2 ledger checkpoint, the codec and domain/session conversion were in-memory only (no migration, filesystem access/save, CLI, or loaded-document workflow); later Feature 3–6 entries below supersede that historical scope. The converted subset validates identities and supported wire semantics; unsupported attributes and metadata are rejected. No M3 roadmap checkbox is complete.

- Feature 3 update (supersedes the prior persistence paragraph's claim that conversion/session workflows are absent): `formats::to_domain(&DigV2)` and `formats::from_domain(&Document)` implement the supported editable subset; `Session::open_dig_bytes` and `export_dig_bytes` are in-memory transactional APIs only. `to_domain` accepts exactly Digital names `In`, `Out`, `And`, `Or`, `Not`, one-bit/default attributes, no transform/rotation/mirror and empty/one label. Reversed segments are accepted. Endpoint graph connectivity makes endpoint junctions connect; interior crossings stay disconnected. Dangling segments, T contacts/endpoint-on-interior, non-pin branches, overlapping/duplicate segments, loops, coincident pins and pin-on-segment-interior are rejected; no rerouting or normalization is silently applied. Export reconstructs a deterministic orthogonal route and checks resulting geometric pin partitions against explicit domain edges, refusing accidental shorts. A bounded O(n²) segment check plus pin/segment checks costs at most 80,000 comparisons; large geometry is refused with a budget error. Domain ID/pin/self-edge/duplicate-edge references are validated. Float positions must be finite integral values exactly representable within i32; no rounding, snapping or saturating casts.

### Feature 4 — bounded file open and atomic session save (partial M3)

- `Session::open_path(io, path, discard_intent)`, `save(io)`, `save_as(io, path, intent)` and `path()` are headless engine operations; Feature 5 exposed the supported single-document subset through the native UI. At that Feature 5 checkpoint there was no CLI; Feature 6 below adds a bounded headless CLI. Recent-file state, hierarchy and resource resolution remain unsupported. `FileIo`/`StagedFile` are injectable seams; `LocalFileIo` takes an explicit absolute base path. Relative paths resolve lexically against that base, never the process cwd; paths remain `PathBuf`/`OsStr`, including non-UTF-8 names.
- Open refuses while simulation is active before filesystem access. Dirty sessions require `DiscardDirty`; refusal occurs before path resolution/read. The local adapter rejects symlinks and non-regular files. It reads at most `4 MiB + 1` bytes from an opened regular file independent of metadata; the extra byte determines oversize. The codec independently enforces its 4 MiB limit. Parse, domain conversion and ID preparation complete before replacing document, saved baseline, path, histories or counters. Any read/oversize/parse/conversion failure leaves them unchanged. Success associates the absolute path, marks clean, clears undo/redo and seeds IDs.
- Save encodes/validates before target inspection or staging. `save` without a path returns typed `PathRequired`; Save As requires explicit `CreateOnly` or `Replace`. Both refuse during simulation before filesystem access. A staging file is exclusively created beside the target with bounded 16-name collision retry; foreign collisions are not modified. Writes complete, then flush, file sync and close precede publication. Replacement uses same-directory rename; create-only uses same-filesystem hard-link publication, atomically no-clobber (the preliminary existence check is only an early error, never the race defense). There is no truncate-first or copy-overwrite fallback. File-operation failures retain the original `io::Error` together with a typed stage and relevant path; open/read, path resolution, target validation, staging, publication and parent sync errors have distinguishable context and useful display text. Pre-publication cleanup failure accompanies the primary failure with cleanup stage/path. After publication, every failure (including both temp-link removal and parent-directory sync failing together) is retained as a structured diagnostic with its stage, path and source, including the leftover temporary-link path. This returns `PublishedDurabilityUnconfirmed`, not a normal failure; saved baseline and association update because publication already happened. Successful saves preserve document IDs and undo/redo history. Failed Save As retains the previous association/baseline.
- Self-authored headless tests inject create, partial-write, flush, file-sync, publish, cleanup and directory-sync failures; cover foreign temp collisions, create-only concurrent-writer race/no-clobber, oversized reads, symlink/directory rejection, transactional open failures and dirty/simulation locks, path-required and codec-refusal no-touch behavior, clean-open ID/history reset, save history/baseline and failed Save As association, plus real-tempdir create/replace/reopen smoke. New regressions cover successful publication followed by remove-temp failure alone and simultaneous remove-temp plus parent-sync failures (all diagnostics and leftover path, with session path/baseline committed) and missing versus permission-denied reads (stage/path and preserved source kind). The race test creates a competing target immediately before atomic hard-link publication. Filesystem behavior was tested only on the current host; Windows/macOS/Linux portability is not claimed.
- Limits/risks: replacement atomicity and power-loss durability depend on the host filesystem. ACL/permissions/xattrs are not preserved, network filesystems are unverified, hostile same-user temp-path substitution and symlink TOCTOU at open are not comprehensively defended, and concurrent replacement writers/platform rename semantics are not comprehensively validated. Existing symlink destinations are refused, not followed/replaced; parent directories are not created. Only strict `.dig` v2 subset described above is supported; v0/v1 and unsupported document data are refused. Hierarchy/resources are not resolved. At the Feature 4 checkpoint, M3 was incomplete including the CLI; Feature 6 below subsequently added a bounded, non-compatible CLI. M3 remains incomplete for migrations, unsupported-data preservation and external Digital comparison.

- The canvas draws and picks them: `src/symbol_tessellate.rs` tessellates the data with `lyon_tessellation` 1.0.23 (non-zero/even-odd compound fills including the `&` counters, stroke caps and joins; curves flattened to at most 0.25 physical pixels; a one-pixel coverage fringe on every edge, because egui gives raw meshes no anti-aliasing), `src/symbol_render.rs` caches the geometry per style, kind and quarter-octave scale bucket and builds one egui mesh per symbol, and `src/canvas.rs` is the world-to-screen transform all drawing and picking goes through. Strokes (1.5 world units) scale with the transform. Colors come from the theme through semantic roles (ink, selection, error); signal colors are reserved for wiring.
- Shape style is a palette choice, Rectangular (default) or IEEE, kept as transient UI state; it is not stored in the document and not persisted. Input and Output look the same in both styles. The default is explicit, not Digital's locale-dependent `IEEEShapes` default.
- A component position is still the center of the drawn symbol (the earlier meaning); pin anchors are reported in world coordinates by `SymbolLayout::anchors` and sit on the 20-unit grid only when the center does. Hit testing uses the symbol bounds plus a 2-point tolerance, not pin or outline geometry.
- Visual check: `just symbol-sheet` rasterizes the meshes of all ten bindings with a small test-only software rasterizer to `reimplementation/target/symbol-sheet.png` (git-ignored). It approximates, and does not replace, a look at the wgpu output; no native-window visual check was made.
- Not yet done: no pan or zoom UI (the zoom is a fixed 1.0), no rotation or per-input inversion, only the two-input layouts of the AND/OR symbols, no persisted style preference, no benchmarks of geometry or mesh cost, and sub-pixel features (very small zoom) are not specially handled by the anti-aliasing fringe. Light/dark rendering and fractional pixels-per-point are covered only by unit tests.
