# Component-editing subset

- EDIT-1 implemented: empty document and in-memory Input, Output, AND, OR and NOT descriptors, positions, labels, validated commands, snapshot undo/redo and dirty state. Headless engine tests exercise history, IDs, invalid commands and redo preservation.
- EDIT-2 implemented: palette, canvas grid, selection, movement, deletion, shortcuts and visible errors. Components are drawn from the original generated symbols (see Vector assets); labels are separate runtime text. Headless egui tests exercise placement, focus ownership, rendered errors, selection, drag cancellation, history and shortcuts; native interaction, all palette choices and light/dark appearance remain unverified.
- EDIT-3 implemented: explicit pin-to-pin wires (click or keyboard pin picking, deletion, undo). A wire joins the two named pins; geometry, crossings and coincident pins never connect anything. Same-direction wires are allowed while editing and judged when simulating.
- SIM-1 implemented (one-bit, acyclic): `src/simulation.rs` compiles pin nets (exactly one output driver per net, no floating receiving pins, no feedback, limits of 10,000 components, 30,000 wires and 80,000 work units); `src/runtime.rs` evaluates Input, Output, AND, OR and NOT with Digital's read-then-publish microstep; `src/engine.rs` owns the runtime outside the document and history, starts transactionally and rejects every edit, undo and redo while it runs; `src/ui.rs` provides Start/Stop/Step/Settle (buttons and F5, Shift+F5, F10, F6), idle/pending/settled/error status, input toggles (panel list, canvas click, Space), text value badges (`= 1`, `= 0`, `= ?`), an edit-lock explanation, cancellation of placement/wire/drag gestures on start, located compile errors in the visible error path and settle chunks of 2,048 work units per frame with a repaint requested while work remains, so Stop is handled between chunks. Headless tests cover the engine and the egui paths (start, toggle, step, settle, stop, edit and undo; invalid circuits; blocked pointer and keyboard edits; gesture cancellation; multi-frame settling with Stop). Digital references: `core/Model.java` (microsteps), `draw/model/NetList.java` (Digital also joins nets by geometry, which this editor deliberately does not), source revision d118dce079b6b8867024d40f9b14dfa667e52106.
- Simulation gaps: compilation and each settle chunk run on the UI thread within the documented limits (no worker, so no cancellation or stale-result handling was needed or built); a toggle is refused while work is pending; unconnected gate inputs are errors where Digital would let them float; no feedback or randomized startup, high-Z, contention, buses, clocks, sequential components, memory, hierarchy, measurement or tests; settle oscillation limits are not applicable because cycles are rejected. Passing these tests is not Digital parity.
- Persistence (partial, not M3 completion): `src/formats.rs` exposes `formats::parse_v2(bytes)`, `formats::serialize_v2(&DigV2)`, and a format-specific `DigV2` model. The subset is strict UTF-8 Digital `.dig` v2 XML with empty circuit attributes, ordered visual elements (`elementName`, empty or one `Label` string entry, integer `pos`), ordered wire endpoints, and absent/empty measurement ordering. Wire endpoint geometry is preserved as written (including diagonal, reversed and zero-length segments); element/wire order, arbitrary element names, signed i32 coordinates, and `None` versus `Some("")` labels round-trip semantically. The deterministic writer emits an XML 1.0 UTF-8 declaration, version 2, empty circuit attributes and the represented visual elements/wires; measurement ordering is omitted because this model cannot represent it. XML text escaping preserves Unicode, tab/LF and CR via numeric references, including CR-versus-LF semantics, and escapes ampersand, less-than and greater-than. Writer errors are typed and include element/field context. Both directions bound element/wire counts at 10,000/30,000 and decoded strings at 4 KiB; parser limits also include 4 MiB input, depth 32 and 64 attributes per XML element, and writer construction is capped incrementally at 4 MiB output. Coordinates are signed i32. The parser checks text outside the document element as literal XML whitespace before entity decoding; entities remain decoded inside fields. The parser rejects v0/v1/future versions and unsupported/extra fields, attributes, resources, rotation, metadata or measurement values rather than discarding data. This remains an in-memory codec only: no migration, domain conversion, filesystem access/save, CLI, or loaded-document workflow; component identities and wire semantics are not validated. No M3 roadmap checkbox is complete.
- Persistence evidence: Digital source revision `d118dce079b6b8867024d40f9b14dfa667e52106`, paths `src/main/java/de/neemann/digital/draw/elements/Circuit.java` (`save(OutputStream)` emits the UTF-8 XML declaration and marshals through XStream; `getxStream()` aliases `circuit`, `visualElement`, `wire`, `attributes` and `vector`), `VisualElement.java`, `Wire.java`, `src/main/java/de/neemann/digital/draw/graphics/Vector.java`, `src/main/java/de/neemann/digital/core/element/ElementAttributes.java`, and `src/test/java/de/neemann/digital/draw/elements/CircuitTest.java`. This slice is scoped to version-2 write shape and represented values; no native Java differential test is claimed. The bundled release example `references/Digital_release/examples/hazard/Hazard.dig` is **v1**, from release `v0.31`; it is not evidence of source-revision v2 compatibility. A read-only source-tree v2 example, `src/main/dig/combinatorial/FullAdderRCSig.dig`, has nonempty root attributes (including Description), so it is deliberately outside this subset; this is not a successful whole-document compatibility result. Serializer and parser tests are self-authored; no Digital fixtures/code/tests/assets were copied. Tests cover semantic round trips, exact empty output, deterministic canonical output, escaping and Unicode/control character boundaries, signed points and wire geometries, outside-root entity offsets, parser grammar/security and budget edges. No native-window checks were run.
- Validation: only headless egui and unit tests were run. No native-window check of the simulation controls (focus order, real-time responsiveness, keyboard use, light/dark appearance) was performed. Because the canvas holds keyboard focus and consumes Tab, the F-key shortcuts are the keyboard route to the simulation controls from the canvas.

## Vector assets

- 25 UI icons and the application icon and splash are original SVGs made with the VectorCraft MCP (`reimplementation/assets/`, inventory in `icons/manifest.toml`, provenance in `assets/PROVENANCE.md`); no Digital artwork was copied or traced.
- PNGs are generated at build time by `reimplementation/build.rs` using `resvg` (icons at 24 and 48 px, app icon at 16-512 px, splash at 512x320 and 1024x640) and are never committed. `just assets-preview` (outside `build.rs`, requires `jq`) copies them to `target/asset-preview/`.
- Not yet done: the icons and brand images are exposed through `src/assets.rs` but are not wired into the UI; no toolbar, menu, window icon or splash screen uses them.
- Component symbols (rectangular and IEEE AND/OR/NOT, shared Input/Output; `assets/components/`) are original VectorCraft SVGs converted at build time into vector data (curves and compound glyph contours preserved, anchors validated against `manifest.toml`) and exposed by `src/symbols.rs`.
- The canvas draws and picks them: `src/symbol_tessellate.rs` tessellates the data with `lyon_tessellation` 1.0.23 (non-zero/even-odd compound fills including the `&` counters, stroke caps and joins; curves flattened to at most 0.25 physical pixels; a one-pixel coverage fringe on every edge, because egui gives raw meshes no anti-aliasing), `src/symbol_render.rs` caches the geometry per style, kind and quarter-octave scale bucket and builds one egui mesh per symbol, and `src/canvas.rs` is the world-to-screen transform all drawing and picking goes through. Strokes (1.5 world units) scale with the transform. Colors come from the theme through semantic roles (ink, selection, error); signal colors are reserved for wiring.
- Shape style is a palette choice, Rectangular (default) or IEEE, kept as transient UI state; it is not stored in the document and not persisted. Input and Output look the same in both styles. The default is explicit, not Digital's locale-dependent `IEEEShapes` default.
- A component position is still the center of the drawn symbol (the earlier meaning); pin anchors are reported in world coordinates by `SymbolLayout::anchors` and sit on the 20-unit grid only when the center does. Hit testing uses the symbol bounds plus a 2-point tolerance, not pin or outline geometry.
- Visual check: `just symbol-sheet` rasterizes the meshes of all ten bindings with a small test-only software rasterizer to `reimplementation/target/symbol-sheet.png` (git-ignored). It approximates, and does not replace, a look at the wgpu output; no native-window visual check was made.
- Not yet done: no pan or zoom UI (the zoom is a fixed 1.0), no rotation or per-input inversion, only the two-input layouts of the AND/OR symbols, no persisted style preference, no benchmarks of geometry or mesh cost, and sub-pixel features (very small zoom) are not specially handled by the anti-aliasing fringe. Light/dark rendering and fractional pixels-per-point are covered only by unit tests.
