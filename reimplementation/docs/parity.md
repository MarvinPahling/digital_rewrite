### Feature 1 — mixed selection and group editing (partial M4)

- Selection is transient and mixed: stable component IDs plus per-segment A/B endpoint masks. Plain selection replaces, Shift adds, Ctrl/Cmd toggles; marquee uses full symbol-bounds containment and selects individual stored wire endpoints inside a normalized rectangle (crossing-only segments are excluded). Ctrl/Cmd+A selects all components and both endpoints of all stored segments. Shift+arrows nudge the full selection by a common 20-world-unit increment; group pointer drags preview without document mutation and commit once on release. Escape, focus loss, pointer loss, modal entry and document replacement cancel active selection gestures. Attributes are exposed only for exactly one selected component.
- `Session::move_selection` and `delete_selection` are headless atomic commands, validate active-simulation lock first, reject stale identities/IDs and unrepresentable component/pin positions before history mutation, preserve redo/IDs on no-op, and create one history snapshot on success. Moving selected endpoints stretches boundary segments; internal segments move both endpoints. Only selected segments that collapse are removed; unrelated raw geometry is not normalized. Deleting a component retains all wire records; selecting either endpoint means deleting that stored segment. This endpoint-delete meaning is explicit in the current UI subset.
- Digital source revision `d118dce079b6b8867024d40f9b14dfa667e52106`: `Circuit.java#getElementsToMove` and `copyElementsInRect` include visual elements matching the rectangle and add each wire endpoint independently when it lies inside; `MouseControllerMoveSelected` moves those selected endpoints. `MouseControllerMoveElement` moves a single visual element and does not generally auto-translate attached wires. The Rust endpoint-mask selection is a representation choice, and this subset does not automatically infer/move adjacent endpoints from selected component pins; this is not characterized as a blanket deviation from Digital's single-element behavior. `delete` and `VisualElement.java#matches(min,max)` document related rectangle/delete semantics.
- Self-authored tests cover modifier toggling, normalized marquee direction, endpoint masks/crossing exclusion, mixed group move/delete, atomic history/undo, stale selection and simulation-lock transactionality. Production egui event tests verify plain replacement, Shift-add, Ctrl-toggle, Escape/focus-loss cancellation without selection loss, and collapsed-wire cleanup across keyboard nudge followed by another move/delete; existing selected-group drag behavior remains covered. No native-window interaction, clipboard integration, or Java differential was run.
- Architectural UI seam reviewed read-only: PhotoCraft `877d58844029967b80e36a964902d309de1be158`, `docs/architecture.md` §§4, 6, 11, `AGENTS.md`, `apps/photocraft/src/main.rs`, and `crates/ui-egui/`; MaterialCraft `4ff5af9af7371613ee37b186e03caf49ee6dbd88`, `crates/ui-egui/src/graph/input.rs` and `graph/gesture.rs`. ### Feature 4 — bounded file open and atomic session save (partial M3)

- `Session::open_path(io, path, discard_intent)`, `save(io)`, `save_as(io, path, intent)` and `path()` are headless engine operations; Feature 5 exposed the supported single-document subset through the native UI. At that Feature 5 checkpoint there was no CLI; Feature 6 below adds a bounded headless CLI. Recent-file state, hierarchy and resource resolution remain unsupported. `FileIo`/`StagedFile` are injectable seams; `LocalFileIo` takes an explicit absolute base path. Relative paths resolve lexically against that base, never the process cwd; paths remain `PathBuf`/`OsStr`, including non-UTF-8 names.
- Open refuses while simulation is active before filesystem access. Dirty sessions require `DiscardDirty`; refusal occurs before path resolution/read. The local adapter rejects symlinks and non-regular files. It reads at most `4 MiB + 1` bytes from an opened regular file independent of metadata; the extra byte determines oversize. The codec independently enforces its 4 MiB limit. Parse, domain conversion and ID preparation complete before replacing document, saved baseline, path, histories or counters. Any read/oversize/parse/conversion failure leaves them unchanged. Success associates the absolute path, marks clean, clears undo/redo and seeds IDs.
- Save encodes/validates before target inspection or staging. `save` without a path returns typed `PathRequired`; Save As requires explicit `CreateOnly` or `Replace`. Both refuse during simulation before filesystem access. A staging file is exclusively created beside the target with bounded 16-name collision retry; foreign collisions are not modified. Writes complete, then flush, file sync and close precede publication. Replacement uses same-directory rename; create-only uses same-filesystem hard-link publication, atomically no-clobber (the preliminary existence check is only an early error, never the race defense). There is no truncate-first or copy-overwrite fallback. File-operation failures retain the original `io::Error` together with a typed stage and relevant path; open/read, path resolution, target validation, staging, publication and parent sync errors have distinguishable context and useful display text. Pre-publication cleanup failure accompanies the primary failure with cleanup stage/path. After publication, every failure (including both temp-link removal and parent-directory sync failing together) is retained as a structured diagnostic with its stage, path and source, including the leftover temporary-link path. This returns `PublishedDurabilityUnconfirmed`, not a normal failure; saved baseline and association update because publication already happened. Successful saves preserve document IDs and undo/redo history. Failed Save As retains the previous association/baseline.
- Self-authored headless tests inject create, partial-write, flush, file-sync, publish, cleanup and directory-sync failures; cover foreign temp collisions, create-only concurrent-writer race/no-clobber, oversized reads, symlink/directory rejection, transactional open failures and dirty/simulation locks, path-required and codec-refusal no-touch behavior, clean-open ID/history reset, save history/baseline and failed Save As association, plus real-tempdir create/replace/reopen smoke. New regressions cover successful publication followed by remove-temp failure alone and simultaneous remove-temp plus parent-sync failures (all diagnostics and leftover path, with session path/baseline committed) and missing versus permission-denied reads (stage/path and preserved source kind). The race test creates a competing target immediately before atomic hard-link publication. Filesystem behavior was tested only on the current host; Windows/macOS/Linux portability is not claimed.
- Limits/risks: replacement atomicity and power-loss durability depend on the host filesystem. ACL/permissions/xattrs are not preserved, network filesystems are unverified, hostile same-user temp-path substitution and symlink TOCTOU at open are not comprehensively defended, and concurrent replacement writers/platform rename semantics are not comprehensively validated. Existing symlink destinations are refused, not followed/replaced; parent directories are not created. Only strict `.dig` v2 subset described above is supported; v0/v1 and unsupported document data are refused. Hierarchy/resources are not resolved. At the Feature 4 checkpoint, M3 was incomplete including the CLI; Feature 6 below subsequently added a bounded, non-compatible CLI. M3 remains incomplete for migrations, unsupported-data preservation and external Digital comparison.
- Test inventory check: compared the pre-Feature-4 source from `git show 48d8d98` with the current test-function names; no preexisting test name was removed. Current `cargo test` reports 84 library tests plus 137 binary tests (220 passed, 1 ignored); counts include separately compiled harnesses and must not be compared as if each were unique coverage. No baseline build was run outside this mission worktree.

### Feature 6 — bounded headless CLI (partial M3)

- Added a separate `digital-rust-cli` binary; native startup remains the existing `digital-rust` GUI. It exposes `open PATH`, `validate PATH`, and `simulate PATH [--input ID=0|1]... [--budget N]`; captures the process startup directory once and resolves the `OsString` path using the existing bounded `Session::open_path`/`LocalFileIo` adapter. It performs no output/file writes.
- `open` deterministically lists imported IDs, supported kinds, escaped labels and wire count, explicitly saying the document has not been simulator-validated. `validate` runs the shared compiler and prints located/subset-aware connectivity diagnostics. `simulate` validates all component-ID assignments (unknown/non-input/duplicate rejected) before runtime start, settles startup and each argument-ordered assignment under one cumulative work budget, and prints output IDs/escaped labels/one-bit values only after all settling succeeds. Defaults to 20,000 work units; accepted explicit budget is 1–80,000 and assignments are bounded to 10,000. Exit codes are 0 success, 1 document/compile/operation/budget failure, 2 usage/option/assignment syntax failure; errors go to stderr, success to stdout.
- `Session::set_input` delegates to the existing runtime and does not alter document, history or dirty state. Native `main.rs` and the CLI now use the same public library engine, format, file-I/O and diagnostic modules rather than separate compiled copies of the engine. Integration tests execute the actual CLI process: relative and absolute Unicode/space paths and escaped labels, unchanged source bytes, a conditional non-UTF-8-path test (execution of the non-UTF-8-host branch is not claimed), open/validate/simulate, missing/non-regular/malformed/oversized/future-version files, unsupported content and geometry, floating/multiple-driver diagnostics plus feedback acceptance (convergence is not claimed), invalid/duplicate assignments, assignment-count/numeric overflow, unknown flags, exhaustion without output, inverter and exhaustive AND/OR truth tables. A fake `FileIo` asserts all three commands perform no file-output operations. A direct session test verifies `set_input` changes transient runtime state only.
- Evidence reviewed read-only: Digital source `d118dce079b6b8867024d40f9b14dfa667e52106`, `cli/Main.java`, `cli/Runner.java`, `cli/cli/Muxer.java`, `core/Model.java`, `draw/elements/Circuit.java`; PhotoCraft `877d58844029967b80e36a964902d309de1be158`, `docs/architecture.md`, `AGENTS.md`, `apps/photocraft/src/main.rs`; MaterialCraft `4ff5af9af7371613ee37b186e03caf49ee6dbd88`, graph UI reference. This implementation is a new Rust-specific command interface; it does not claim Digital CLI compatibility or copy reference code. It has not been compared against the Java CLI.
- Gaps: the parser remains strict v2 only; migration, hierarchy/resource resolution, feedback startup/oscillation compatibility, clocks, buses/high-Z, stateful and non-one-bit components, Digital's other CLI commands/options and exact Java exit behavior are unsupported. Compilation supports only the existing one-bit component subset; feedback is accepted but a successful compile says nothing about runtime convergence. Integration does not establish Windows/non-UTF-8 portability, all reference diagnostics, large-circuit performance or permissions behavior. CLI is headless only and creates no GUI. Native label editing and an automated supported-subset exit workflow are added in Feature 7; this does not complete the broad M4 checklist or its Digital comparison gate.

Hit testing uses the symbol bounds plus a 2-point tolerance, not pin or outline geometry.

### Feature 9 — one-bit constant source (partial component-catalog parity)

- Added `ComponentKind::Const` with one output and no inputs, a typed `bool` configured value defaulting HIGH, descriptor/palette registration, validated session editing (`set_constant_value`), snapshot undo/redo, and simulation/file-edit locking. No-op and invalid commands preserve history/redo. Constants initialize their driven nets before the first gate batch; they are not interactive Inputs and never enter the scheduled gate queue.
