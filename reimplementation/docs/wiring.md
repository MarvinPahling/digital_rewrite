# Geometric wiring: current status and limits

The integer segment implementation remains staged and isolated in `src/geometric_wiring.rs`. It is **not** the `Document` wiring representation and must not be presented as a completed editor feature. Existing documents, editor, compiler and `.dig` codec remain legacy explicit pin-pair based. Do not convert, hide or discard existing wires; opening/import behavior remains unchanged.

Implemented here: signed-i32 segments, deterministic normalization, staged transactional edits and local snapshot undo/redo. Normalization preserves diagonal interiors: a non-endpoint lying on a diagonal does not cut it; a diagonal endpoint can cut an orthogonal segment, and shared endpoints remain a contact. Orthogonal endpoint-on-segment contacts are split; proper interior crossings remain separate. IDs allocated during normalization are advanced beyond the edit owner's monotonic high-water mark, which is not rolled back by undo/delete. Failed and no-op operations leave the staged owner unchanged. Normalization has a 5,000,000-work cap, including a preflight upper bound for generated pieces and bounded quadratic merge scans; this is a resource safeguard, not a compatibility guarantee.

**Not implemented / blockers to feature completion:** the `Wiring` variant is not embedded in `domain::Document`; there are no geometry commands on the existing engine `Session`, so dirty/saved baselines, runtime locking, diagnostics/trace behavior, undo/redo and IDs are not shared. The `GeometricSession` must not be used as an alternate document owner. No component/pin-layout based canonical migration exists; conversion must reject fractional or unrepresentable anchors, coincident logical edges, and any topology change atomically. Geometric compile and export/save refusal are not yet wired into production. No geometric codec, GUI gestures, or compiler connectivity activation is claimed. These are required before feature 1 can be called complete.

New implementation and tests are self-authored. Read-only behavioral evidence: Digital revision `d118dce079b6b8867024d40f9b14dfa667e52106`, `draw/elements/Wire.java`, `WireConsistencyChecker.java`, `WireMerger.java`, `draw/model/NetList.java` and `Net.java`; the implementation is informed by the distinction between endpoint contacts and interior crossings. No reference code/tests/fixtures/assets were copied. The rewrite licensing/reuse policy is unresolved; this is not a clean-room or legal-clearance determination.
