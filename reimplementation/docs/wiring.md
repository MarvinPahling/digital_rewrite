# Geometric wiring: document/session integration (partial)

`domain::Document::wires` is now the mutually exclusive `Wiring` enum: `LegacyPinPairs` remains the default for new/edit/imported documents, and `GeometricSegments` owns normalized integer segments. Existing `.dig` v2 import therefore keeps its prior legacy behavior. There is no geometric codec yet.

The existing engine `Session` owns geometric batch-add, segment/endpoint move, split, delete and merge operations. They validate/normalize before committing one document snapshot, share undo/redo, dirty tracking, monotonic segment IDs and the simulation edit lock; errors and no-ops leave document/history unchanged. Component movement/deletion leaves independent geometric segments intact. The redundant standalone geometric history owner was removed; `normalize` is the reusable pure operation.

`Session::migrate_to_geometric_wiring` is transactional and uses the existing format conversion path's shared component pin placement and canonical router. Conversion requires exact i32 anchors/routes; the import boundary verifies that the canonical route reconstructs the same pin connectivity. Unsupported/ambiguous routes fail before mutation. Geometric documents are explicitly rejected by the simulator compiler and domain-to-`.dig` exporter; session save encodes before touching the filesystem and propagates the typed refusal. This is not an empty-wire fallback.

The native editor, CLI import and `.dig` import remain in legacy mode. Geometric drawing/gesture activation, geometric serialization and connectivity compilation remain later work. The enum's migration path is headless only and does not imply geometric UI support or Digital parity.

Normalization preserves diagonal interiors, splits orthogonal endpoint contacts, and leaves proper interior crossings separate. IDs remain monotonic through normalized edits and history. Its 5,000,000-work cap bounds generated-piece and merge scans.
