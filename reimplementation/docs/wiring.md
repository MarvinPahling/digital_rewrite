# Geometric wiring: document/session integration (partial)

`domain::Document::wires` is the mutually exclusive `Wiring` enum: `LegacyPinPairs` remains the default for new/edit/imported documents, and `GeometricSegments` stores integer segments. The editor, `.dig` import/export, and CLI continue to use legacy mode; geometric export still refuses rather than discarding geometry.

The existing engine `Session` owns geometric batch-add, segment/endpoint move, split, delete and merge operations. They validate/normalize before committing one document snapshot, share undo/redo, dirty tracking, monotonic segment IDs and the simulation edit lock; errors and no-ops leave document/history unchanged. Component movement/deletion leaves independent geometric segments intact. `Session::migrate_to_geometric_wiring` builds a canonical route candidate, normalizes it, then compares final candidate pin partitions to the legacy pin-pair partitions before mutation. Both connectivity adapters return the same canonical ordering (pins sorted within each partition, then partitions sorted), independent of union-find roots, route order or geometry. This connectivity-only comparison intentionally accepts incomplete electrical circuits; a topology-changing migration is rejected transactionally.

## Feature 2 geometric compiler scope

`simulation::compile` now selects connectivity by `Wiring` mode. Legacy pin-pair validation/net grouping remains unchanged, including its lack of position validation (fractional finite legacy placements remain valid). Geometric compilation uses toolkit-neutral `pin_geometry` integer anchors and `topology::resolve_detailed`; it never normalizes, rounds or converts final integer points through `f32`. Only exact finite integral component-center positions in signed-i32 range, and checked i32 origin/offset arithmetic, are accepted. Supported pin offsets are Input/Out/Const `(0,0)`, AND/OR/XOR inputs `(0,0),(0,40)` and output `(60,20)`, NAND/NOR/XNOR output `(80,20)`, NOT input `(0,0)` and output `(40,0)`; positions are first converted from artwork-bounds center to Digital origin using shared symbol bounds.

Connectivity joins equal endpoints and coincident pins. Proper crossings, endpoint-on-interior contacts, and pins in segment interiors remain disconnected unless the geometry explicitly splits at that point. Diagonal segments are allowed as endpoint edges. Zero-length and duplicate-ID segments and over-budget work are rejected with typed diagnostics. Wire-only connected nets and unused output singleton nets are retained; isolated receiver pins and floating receiver nets are separately diagnosed, and multi-driver errors report sorted pins and segment IDs. Feedback cycles are not rejected and use the existing runtime scheduler unchanged.

This is only the existing one-bit, single-driver component subset. It is not Digital `DataBus` parity and does not implement tri-state/high-Z/contention, buses, labels/tunnels, geometric `.dig` persistence, or UI geometric drawing. Normalization remains an editing/migration operation only; overlapping raw segments are not silently normalized by compile. `MAX_COMPONENTS`, `MAX_WIRES`, `MAX_WORK`, and topology work bounds remain enforced.
