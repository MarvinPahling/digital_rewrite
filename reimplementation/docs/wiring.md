# Geometric wiring (authoritative document model)

`Document::wires` uses a geometric-only `Wiring` wrapper over integer `Segment` endpoints. There is no pin-pair connection variant, compiler adapter, export adapter, migration API, or wire-ID counter. New documents, `.dig` v2 imports, editor routes, CLI inspection, compilation and serialization all use this representation. Each segment ID is stable within the document; the engine advances its segment-ID high-water mark transactionally, including across undo. `Session::connect` is only a convenience command that creates actual routed segments between checked pin anchors; it stores no parallel logical edge.

## Connectivity and simulation

`simulation::compile` obtains pin coordinates through toolkit-neutral `pin_geometry` and resolves endpoint topology with `topology::resolve_detailed`. Only finite, exactly integral component centers in signed-i32 range and checked i32 origin/offset arithmetic are accepted. Connectivity joins equal wire endpoints and pins at those endpoints. Proper crossings, endpoint-on-interior contacts and pins in segment interiors remain disconnected unless an edit explicitly splits the selected segment. Import/open, compile and serialization do not normalize or autoattach raw geometry. Normalization, merge and split are explicit editing operations, never hidden compiler behavior. Diagonal segments and coincident pins are valid; endpoint equality, not orthogonality, determines connectivity. Engine placement and movement validate every derived pin anchor before publishing, preventing origin-offset overflow and preserving document/history/ID state on rejection. Zero-length/duplicate-ID segments and over-budget work produce typed diagnostics. Wire-only nets and unused output singleton nets are retained; isolated receiving pins, floating receiver nets and multiple drivers are diagnosed with component/pin and segment membership where applicable. Feedback remains accepted by the existing staged runtime.

This remains the one-bit, single-driver component subset—not Digital `DataBus`, tri-state/high-Z/contention, memory, sequential logic, hierarchy or full Digital behavior. Strict v2 import/export preserves stored endpoint records without normalization or requiring successful compilation; unsupported document fields are refused. The compiler's bounds are 10,000 components, 30,000 segments and 80,000 work units. Selected-segment deletion preserves all other stored records and intentionally does not globally merge or normalize them. Component movement/deletion does not infer adjacent wire movement from pin attachment.

## Mixed selection and group editing (Feature 1)

The editor's transient selection stores component IDs and independent A/B endpoint masks per geometric segment; it is not serialized. Plain click/marquee replaces, Shift adds, Ctrl/Cmd toggles, and Ctrl/Cmd+A selects all components and wire endpoints. Marquee includes a component only when its whole drawn symbol bounds lie inside the rectangle; each wire endpoint is independently included when it lies inside, so a crossing-only segment is excluded. A selected component does not implicitly select wire endpoints at its pins. This is a bounded mixed-selection policy, not a claim of Digital's exact interaction model.

Group movement previews only in the canvas and commits one atomic engine transaction at release, using one common 20-unit snapped delta. Selecting one endpoint stretches its segment; selecting both moves the complete segment. Digital source revision `d118dce079b6b8867024d40f9b14dfa667e52106` has `Circuit.getElementsToMove`/`copyElementsInRect` collect wire endpoints by rectangle membership, then `MouseControllerMoveSelected` moves those endpoints. Its separate `MouseControllerMoveElement` moves a visual element without generally auto-moving attached wires. This subset likewise does not infer endpoint movement from component-pin attachment. Moving/deleting components never invokes global normalization. Only a moved selected segment that collapses is removed; transient selection is reconciled against surviving IDs after group moves. Deleting a selected wire endpoint deletes its stored segment; deleting components leaves all wires untouched. Undo restores the transaction in one step. Stale IDs, arithmetic/precision errors, derived component-pin overflow and simulation lock are checked before publishing changes. Escape, focus loss, PointerGone, modal entry and document replacement cancel the UI preview; camera arrows remain pan, while Shift+arrows nudge selection.

Digital behavior evidence (read-only source revision `d118dce079b6b8867024d40f9b14dfa667e52106`): `gui/components/CircuitComponent.java` `MouseControllerSelect` and `MouseControllerMoveSelected`; `draw/elements/Circuit.java#getElementsToMove`, `copyElementsInRect` and `delete`; `draw/elements/VisualElement.java#matches(min,max)`. Digital rectangle selection requires full symbol containment, gathers wire endpoints independently for movement, and deletes a wire when either endpoint is in the rectangle. The Rust editor keeps endpoint masks explicit to support mixed selection. Headless tests cover modifier state, reverse marquee direction, endpoint masks/crossing exclusion, plain-wire replacement and engine move/delete transactionality; production egui tests cover selection modifiers/cancellation, group nudge, collapsed-segment reconciliation and continued move/delete. Native-window and Java differential checks were not run.

## Feature 3 regressions and canvas precision boundary

- Canvas R is gated on the frame not being cancelled. Escape, focus loss, modal entry, and `PointerGone` clear gestures without allowing another queued R key in that frame to mutate the selected document. Production egui-event regressions send Escape+R and PointerGone+R together and verify document, dirty state and undo boundary remain unchanged.
- Orientation regressions include literal independently calculated mirrored-quarter-turn AND/NOT bounds and every pin in both rectangular and IEEE styles. The engine case combines asymmetric symbols and separately selected A/B wire endpoints, pins expected transformed centers and integer endpoints, and checks overflow preserves document, redo state, and ID high-water marks; simulation lock precedes invalid selection/orientation validation.
- Clipboard placement preview is materialized through the same fragment-to-document geometry helper used by painting. With a stationary canvas pointer, the UI test rotates a fragment containing an asymmetric NOT and a wire, then compares preview and Enter-committed symbol bounds, resolved pins, and complete wire endpoints.
- Integer wire endpoints now project directly from signed-i32 values through f64 camera math rather than an intermediate f32. Symbol artwork remains f32: component centers beyond ±1,048,576 world units are withheld with a visible exact-rendering-range diagnostic. Auto-fit and route/interior editing report their bounds for oversized integer wire geometry; rendering retains exact wire points. Compiler connectivity still accepts exact integral i32 geometry. This documents a UI precision/interaction limit, not arbitrary-i32 artwork, fit, picking, or routing support.

## Canvas route gestures (Feature 4)

Wire mode routes between pins, existing endpoints, or an exact signed-i32 integer point on one named segment. Pointer selection is deterministic: pins first, then endpoints, then segment interiors; within that priority, nearest wins and stable pin/segment/coordinate keys break ties. At an interior crossing the selected `SegmentInterior` carries that segment ID, so only that segment is split by the engine route command. Other crossing segments are intentionally not split or connected. To explicitly choose another coincident candidate, keep the pointer over the ambiguity and press Tab/Shift+Tab to cycle candidates before clicking; keyboard Tab also navigates visible pins, endpoints, and exact segment midpoints (including an exact integer midpoint where available), and Enter starts/finishes a route. The current pointer candidate drives the marker, preview, Enter and click; keyboard focus selects among coincident pointer candidates and remains available to Enter when the pointer is not over a target. Thus moving from a formerly focused target to a distinct target cannot leave Enter committing the old target. Candidate deduplication preserves order with expected-linear hashing, and each Tab rebuilds from current geometry so stale targets are not cycled or committed. Focused target identity/coordinates and route start are shown in the controls; the active pointer target and starting target are themed on-canvas markers.

The preview uses the same orthogonal L-route planner and orientation (`Shift+W` / Flip route) as `Session::route_geometric`; commit revalidates target identities and updates document geometry in one history snapshot. At a crossing, only the selected segment ID is split; the crossing record is untouched. Existing pin endpoints are protected and are not auto-attached to segment interiors. A targeted interior split is atomic with route insertion. Palette placement and component movement snap the logical origin (using the shared per-symbol center/origin offset) to the 20-unit grid; asymmetric artwork bounds do not shift pin anchors off-grid. Escape, focus loss, pointer loss, modal entry and simulation start cancel the draft; start/stop/file commands continue through the Session/UI lifecycle. Selection and Delete remain available outside wire mode. Deleting a selected segment removes only that record and preserves all others. Junction dots represent stored endpoint degree >2, not pins or geometric crossings. Single-component movement/deletion leaves wires stationary; this editor does not infer adjacent endpoints from component attachment. Group movement uses explicit rectangle/end-point selection rather than automatic attachment traversal.

Headless egui production-event tests cover pointer routes from an interior to an endpoint, keyboard routing from a segment midpoint, one-step undo/redo, marker/preview/Enter/click agreement both with Tab-selected and no-Tab hover targets, stale-target rebuilding and 90,000-candidate deduplication without timing assertions. Engine regressions verify an explicitly targeted crossing split leaves the nonselected crossing segment unchanged. CLI subprocess tests demonstrate crossing independence, explicit-junction multi-driver rejection, one-driver four-way fanout, a genuine two-segment T whose branch endpoint touches an unsplit trunk interior (rejected with the floating receiver's branch-segment context), the separate receiver-pin-on-interior disconnection, successful HIGH/LOW receiver simulation after splitting the T trunk into two endpoint segments, unchanged source bytes and located diagnostics. Public compiler evidence and bounds are listed in `docs/parity.md`. Picking uses the shared canvas transform and follows pan/zoom. Native-window interaction and Java differential checks were not run; this subset is not full M4 or Digital parity.

Self-authored simulation regression fixtures encode explicit routed `Segment` endpoints from shared symbol pin geometry. Feedback, startup, trace, fanout, truth-table and CLI paths use the same geometric document representation as production. They avoid relying on coincident pins or a hidden pin-pair fallback.

Behavioral evidence inspected read-only: Digital source revision `d118dce079b6b8867024d40f9b14dfa667e52106`, `draw/model/Net.java#tryMerge/contains`, `NetList`, `ModelCreator`, `ModelEntry`, `Wire`, `WireConsistencyChecker`, `VisualElement#getTransform/getPins`, `GenericShape#createPins`, `InputShape#getPins`, and `OutputShape#getPins`. This documents a supported subset and does not claim full parity, Java differential coverage, or native-window verification. References were not modified.

## Clipboard geometry boundary (Mission Feature 2)

Clipboard export uses explicit mixed-selection IDs/masks, not a guessed rectangle or net traversal. It validates every selected identity; a component is included as a whole, and a segment is included only for `EndpointMask::BOTH`. A/B-only segments are omitted in full (never clipped), and component pins do not infer attached endpoints. Raw segment endpoint order/orientation is retained. This selection policy deliberately follows Digital source `d118dce079b6b8867024d40f9b14dfa667e52106`, `draw/elements/Circuit.java#copyElementsToMove` for complete visual elements and two-ended wires, adapted to the editor's explicit endpoint-mask selection.

Cut is the documented safe variant, not exact Digital deletion: clipboard publication must succeed before mutation, then only exported components and complete wires are deleted. Partial boundary records remain, with a visible status message. Digital `CircuitComponent.java#createCutAction` publishes `CircuitTransferable` before calling `ModifyDeleteRect`, and `Circuit.java#delete(min,max)` removes wires with either endpoint in the rectangle. No clipping, attachment inference, topology normalization or compilation occurs on Rust paste. The bounded list codec shares the strict XML parser; only ten current component kinds and the typed `Label`, Const `Value`, quarter-turn `rotation`, Boolean `mirror`, and applicable binary-gate `wideShape` payloads are supported. Unsupported attrs/classes/references and automatic Digital `CopiedElementLabelRenamer` label-collision behavior remain rejected/unimplemented. Mission Feature 6 adds a single integrated production-event regression through the injected clipboard and clipboard-list codec; the host OS clipboard itself is unverified. The Feature 3 parity note documents orientation transforms and placement-draft R behavior.
