# Geometric wiring (authoritative document model)

`Document::wires` uses a geometric-only `Wiring` wrapper over integer `Segment` endpoints. There is no pin-pair connection variant, compiler adapter, export adapter, migration API, or wire-ID counter. New documents, `.dig` v2 imports, editor routes, CLI inspection, compilation and serialization all use this representation. Each segment ID is stable within the document; the engine advances its segment-ID high-water mark transactionally, including across undo. `Session::connect` is only a convenience command that creates actual routed segments between checked pin anchors; it stores no parallel logical edge.

## Connectivity and simulation

`simulation::compile` obtains pin coordinates through toolkit-neutral `pin_geometry` and resolves endpoint topology with `topology::resolve_detailed`. Only finite, exactly integral component centers in signed-i32 range and checked i32 origin/offset arithmetic are accepted. Connectivity joins equal wire endpoints and pins at those endpoints. Proper crossings, endpoint-on-interior contacts and pins in segment interiors remain disconnected unless callers explicitly split geometry. Engine placement and movement validate every derived pin anchor before publishing, preventing origin-offset overflow and preserving document/history/ID state on rejection. Diagonal segments are valid. Zero-length/duplicate-ID segments and over-budget work produce typed diagnostics. Wire-only nets and unused output singleton nets are retained; isolated receivers, floating receiver nets and multiple drivers are diagnosed. Feedback remains accepted by the existing staged runtime.

This remains the one-bit, single-driver component subset—not Digital `DataBus`, tri-state/high-Z/contention, memory, sequential logic, hierarchy or full Digital behavior. Import/export preserve stored geometry without normalizing or requiring successful compilation; unsupported document fields are still refused by the strict v2 codec. The bounded geometric normalization and segment edit commands remain explicit operations. Component movement/deletion leaves stored wire geometry stationary.

## Canvas route gestures (Feature 4)

Wire mode routes between pins, existing endpoints, or an exact signed-i32 integer point on one named segment. Pointer selection is deterministic: pins first, then endpoints, then segment interiors; within that priority, nearest wins and stable pin/segment/coordinate keys break ties. At an interior crossing the selected `SegmentInterior` carries that segment ID, so only that segment is split by the engine route command. Other crossing segments are intentionally not split or connected. To explicitly choose another coincident candidate, keep the pointer over the ambiguity and press Tab/Shift+Tab to cycle candidates before clicking; keyboard Tab also navigates visible pins, endpoints, and exact segment midpoints (including an exact integer midpoint where available), and Enter starts/finishes a route. The current pointer candidate drives the marker, preview, Enter and click; keyboard focus selects among coincident pointer candidates and remains available to Enter when the pointer is not over a target. Thus moving from a formerly focused target to a distinct target cannot leave Enter committing the old target. Candidate deduplication preserves order with expected-linear hashing, and each Tab rebuilds from current geometry so stale targets are not cycled or committed. Focused target identity/coordinates and route start are shown in the controls; the active pointer target and starting target are themed on-canvas markers.

The preview uses the same orthogonal L-route planner and orientation (`Shift+W` / Flip route) as `Session::route_geometric`; commit revalidates target identities and updates document geometry in one history snapshot. A targeted interior split is atomic with route insertion. Palette placement and component movement snap the logical origin (using the shared per-symbol center/origin offset) to the 20-unit grid; asymmetric artwork bounds do not shift pin anchors off-grid. Escape, focus loss, pointer loss, modal entry and simulation start cancel the draft; start/stop/file commands continue through the Session/UI lifecycle. Selection and Delete remain available outside wire mode. Junction dots represent stored endpoint degree >2, not geometric crossings. Component move preview continues to move only the symbol and its pin anchors; stored wire geometry stays stationary, matching the current Digital single-component move subset. Group movement and attached-wire translation are not implemented.

Headless egui production-event tests cover pointer routes from an interior to an endpoint, keyboard routing from a segment midpoint, one-step undo/redo, marker/preview/Enter/click agreement both with Tab-selected and no-Tab hover targets, stale-target rebuilding and 90,000-candidate deduplication without timing assertions. Engine regressions verify an explicitly targeted crossing split leaves the nonselected crossing segment unchanged. Picking uses the shared canvas transform and therefore follows pan/zoom. Native-window interaction and Java differential checks were not run; this subset is not a claim of full M4 or Digital parity.

Self-authored simulation regression fixtures encode explicit routed `Segment` endpoints from shared symbol pin geometry. Feedback, startup, trace, fanout, truth-table and CLI paths use the same geometric document representation as production. They avoid relying on coincident pins or a hidden pin-pair fallback.
